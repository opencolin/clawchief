# Release v1.0 — Hands and senses

> Worked example: **Pied Piper.** Principal **Richard Hendricks** (CEO); AI chief of
> staff **Anton**; **Gilfoyle** owns Security Ops & IT infrastructure; the
> competitor to watch is **Gavin Belson / Hooli**.

In v0.1 you stood up a container that texts you back. In v0.5 you gave it a self —
Anton's persona and Richard's real priorities, all in data files. So far Anton can
only reason over what you typed into the workspace. This release gives Anton
**hands and senses**: the four operating skills (the *how*), **Tavily** web search
(live world), and **gog** Google Workspace (your real Gmail, Calendar, Sheets).

By the end, Anton stops being "knows your files" and becomes "knows your files
**and** the live world" — and can optionally read your real calendar.

---

## Learning outcomes

By the end of this release you can:

- **Load and verify the four skills** (`executive-assistant`, `business-development`,
  `daily-task-manager`, `daily-task-prep`) and explain why they hold the *how* while
  your data files hold the *who/what/state* (the five separations).
- **Enable the OpenClaw first-party Tavily plugin** with the API key stored only in
  the container state volume, and run a live web search that returns a real source URL.
- **(Optional) Authenticate gog headlessly** against your Google account with
  **least-privilege OAuth scopes**, then have Anton read your calendar.
- **Apply Gilfoyle's least-privilege posture**: read-mostly gog scopes,
  `--gmail-no-send`, and never letting a key touch the repo.
- Tell the difference, architecturally, between adding a *capability* (a plugin /
  CLI) and adding *workflow* (a skill) — neither required editing model code.

## Lab steps

### Part A — Skills (the *how*)

**1. Confirm the four skills are loaded.**
`./docker/clawchief-up.sh all` already overlaid the `skills/` pack into the live
workspace. List them and confirm all four are present.

```bash
$EXEC skills list
```

Expected: `executive-assistant`, `business-development`, `daily-task-manager`,
`daily-task-prep` all appear. If any are missing, re-run the overlay step
(idempotent): `./docker/clawchief-up.sh overlay`.

**2. Read what each skill owns (30-second tour, no commands).**
These four are the *how* — reusable, shareable procedures with **no personal data**:

| Skill | Owns | Reads first (your data) |
|---|---|---|
| `executive-assistant` | inbox triage, calendar checks, scheduling, the EA sweep | `priority-map.md`, `auto-resolver.md`, `tasks.md`, `TOOLS.md` |
| `business-development` | outreach tracker, lead status, prospect pipeline | `priority-map.md`, `auto-resolver.md`, `partners.md` |
| `daily-task-manager` | the canonical live task list across sessions | `clawchief/tasks.md` |
| `daily-task-prep` | the safe early-morning refresh of `## Today` | `tasks.md`, `priority-map.md` |

The lesson: **policy + state are data; workflow is code; persona is data.** The
skills here never mention Richard or Pied Piper — they read your data files at run
time. (See `workshop/modules/make-it-yours.md`.)

**3. Prove the skill drives behavior, not the model's guesswork.**
Ask Anton to act *as* the executive assistant. With no tools wired yet it will tell
you what it would do and which inputs it needs — that's the skill's workflow talking.

```bash
$EXEC agent --agent main --message "Use the executive-assistant skill. Walk me through exactly what you would check for a morning inbox-and-calendar sweep, and name which workspace files and which tool you'd use."
```

Expected: Anton references the `executive-assistant` workflow — reading
`priority-map.md` / `auto-resolver.md` / `tasks.md`, and naming **gog** as the
Gmail/Calendar tool. (It cannot actually read mail yet; that's Part C.)

### Part B — Tavily web search (the senses)

**4. Enable the OpenClaw first-party Tavily plugin — key in the state volume only.**
Get a key at tavily.com (`tvly-…`). Inject it with `config set` from your shell so it
lands in the **`clawchief-state` volume**, never in a tracked file. Substitute your
real key for `tvly-REPLACE_ME`.

```bash
$EXEC config set plugins.entries.tavily '{"enabled":true,"config":{"webSearch":{"apiKey":"tvly-REPLACE_ME"}}}' --strict-json
```

**5. Verify the plugin loaded.**

```bash
$EXEC plugins list | grep -i tavily      # → tavily ... enabled
```

Expected: a line containing `tavily` marked **enabled**. If it's enabled but later
returns no results, restart the gateway and re-check (see Troubleshooting).

**6. Run a live search and demand a source URL.**
This is the wow beat — see "Demo" below for the full expected output.

```bash
$EXEC agent --agent main --message "Use your web search capability to find one recent, real development about Nebius or AI agent frameworks. Give me a 2-sentence summary and include the source URL."
```

**7. Tie the sense to a skill (why this matters for Pied Piper).**
Web search is exactly how `business-development` verifies a prospect's real website
and public email before it ever touches the tracker — and how Anton checks what
**Hooli** is up to.

```bash
$EXEC agent --agent main --message "Use web search to find the official company website and a public contact route for Nebius. Return the verified URL only — do not guess."
```

Expected: a real `https://…` Nebius domain, surfaced from search rather than
invented. That "verify before you record" instinct is the BD skill's core rule.

### Part C — gog Google Workspace (optional but recommended)

> Skip to "Security checklist" if you don't have a Google OAuth client. Tavily +
> skills already satisfy this release's Definition of Done.

The container is already built with `gog` baked in and the encrypted **file** keyring
configured (`GOG_HOME=/home/node/.gog`, `GOG_KEYRING_BACKEND=file`,
`GOG_KEYRING_PASSWORD` from `docker/.env`). You set `GOG_KEYRING_PASSWORD` back in
the v0.1 `.env` step. Full reference: `SETUP-GOG.md`.

**8. Load your OAuth desktop-client credentials into the container.**
Copy your downloaded client-secret JSON into the running container as `cs.json`
(kept out of the repo — `.gitignore` blocks `*client_secret*` / `*credentials*`),
then register it with gog. Replace the host path with your real file.

```bash
docker compose -f docker/docker-compose.yml cp /path/to/your_client_secret.json clawchief:/home/node/cs.json
$EXEC gog auth credentials /home/node/cs.json
```

**9. Add your account headlessly with least-privilege scopes.**
Request **only** the services these skills use right now — Gmail, Calendar, Sheets.
The `--remote` flow prints a URL; approve it in your browser and paste the code back.
Replace `you@example.com` with the account Anton operates as.

```bash
$EXEC gog auth add you@example.com --services gmail,calendar,sheets --remote
# → opens a URL: approve in your browser, copy the code, paste it back at the prompt
```

**10. Verify the account and read the calendar (least-privilege smoke test).**

```bash
$EXEC gog auth list
$EXEC gog calendar calendars -a you@example.com --json --results-only
$EXEC gog calendar events --all -a you@example.com --days=2 --max=20 --json --results-only
```

Expected: your account listed; your calendars enumerated; up to 20 real events for
the next two days as JSON. If Gmail later works but Calendar/Sheets don't, your OAuth
scopes are wrong — fix per `SETUP-GOG.md` "Stop conditions".

**11. Have Anton read the real calendar through the skill.**
Now the executive-assistant skill has a sense to act on.

```bash
$EXEC agent --agent main --message "Use the executive-assistant skill and gog to read my calendar for the next 2 days. Summarize the principal-owned meetings and flag any conflicts. Do not send any email."
```

Expected: Anton runs the gog calendar read and returns a short, decisive summary of
*your* real upcoming meetings — files (the *how*) + senses (gog) working together.

## Demo / what you'll see

**The beat:** Anton answers a question whose answer is *not* in any workspace file,
and cites where it learned it. Run step 6. You should see something shaped like the
verified `demos/tavily-search.md` output (live data, so exact figures will differ):

```
Nebius Group posted first-quarter 2026 revenue of $399 million, up roughly 684%
year over year on booming demand for AI cloud infrastructure. It also signed a
new AI infrastructure deal with Meta in March to accelerate capacity buildout.

Source: https://www.reuters.com/technology/nebius-reports-higher-quarterly-capex-ai-cloud-expansion-2026-05-13
```

The tell that it's real: a **clickable source URL** Anton could not have memorized,
and figures that change run to run. That URL is the difference between an assistant
that pattern-matches and one that *checked*.

**Optional gog beat (step 11):** ask for "the next 2 days" and watch Anton read your
actual calendar and call out the real meeting you have tomorrow — the moment the lab
stops being a toy and starts touching your life.

## Security checklist (Gilfoyle)

> "Your chief of staff can read your email and spend your money. Treat its
> credentials accordingly." — `workshop/modules/security-hardening.md`

This release introduces **two** new secrets (Tavily key, Google OAuth) — the highest
secret-surface jump in the workshop. Four concrete checks:

1. **No secret reached the repo.** The Tavily key went into the `clawchief-state`
   volume via `config set`; the OAuth JSON went into the container, not git. Prove it:

   ```bash
   git status
   git diff | grep -iE 'tvly-|sk-|BEGIN .*KEY|client_secret' && echo "LEAK — STOP" || echo "clean"
   ```

   `.gitignore` already blocks `docker/.env`, `*client_secret*.json`,
   `*credentials*.json`, `gog-home/`, `.gog/` — confirm none are staged anyway.

2. **Least-privilege gog scopes.** You requested only `gmail,calendar,sheets` — not
   Drive/Docs/Contacts — because the four current skills don't need them. Widen scopes
   only when a skill actually requires write/extra access. One Google project, one
   operating account, so a leak is contained and auditable.

3. **`--gmail-no-send` belt-and-suspenders.** Your test prompts said "do not send any
   email," but don't rely on prompt discipline. When you wire any cron or automated EA
   sweep that uses gog Gmail, pass `--gmail-no-send` so a Gmail send is **hard-blocked**
   at the tool layer regardless of what the model decides.

4. **Rotate anything seen in plaintext.** If your `tvly-…` key or OAuth client landed
   in shell history, a screen-share, or a ticket, treat it as compromised: rotate in
   the provider console and re-inject with `config set …` into the state volume. The
   gateway still binds **loopback** with **no published ports** — drive it via
   `docker compose exec`, never an exposed dashboard.

## Definition of done

You pass this release when **all** of the following are true:

- [ ] `$EXEC skills list` shows all four skills: `executive-assistant`,
      `business-development`, `daily-task-manager`, `daily-task-prep`.
- [ ] `$EXEC plugins list | grep -i tavily` shows **enabled**.
- [ ] The step-6 search returns a 2-sentence summary **with a real `https://` source URL**.
- [ ] `git diff | grep -iE 'tvly-|sk-|client_secret'` finds **nothing** (no secret tracked).
- [ ] **(If doing gog)** `$EXEC gog auth list` shows your account, and
      `$EXEC gog calendar events --all -a … --days=2 …` returns real events as JSON.
- [ ] **(If doing gog)** scopes are `gmail,calendar,sheets` only — nothing broader.

Fail and fix if: the search answer has no URL (plugin not enabled / gateway not
restarted), any secret shows in `git diff`, or Gmail authed but Calendar didn't
(wrong OAuth scopes).
