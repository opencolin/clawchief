# Release v0.5 — Give it a self

> **The one-line promise:** the agent stops being a generic model and becomes
> *your* chief of staff — with a name, a boss, and your real priorities.
>
> By the end of this release the container introduces itself as **Anton**, knows it
> works for **Richard Hendricks**, and answers "what matters today?" from a
> source-of-truth workspace *you* control — no skills changed, only data.

Second release of *Build Your Own Chief-of-Staff AI*. v0.1 gave you a live box that
thinks on your key. v0.5 gives it a **self**: persona + the source-of-truth layer.
The whole lesson here is **policy and identity are data, workflow is code** — you
re-theme the entire assistant by editing four files.

Companion reading: `../modules/make-it-yours.md` and `../modules/architecture.md`
(the five separations).

---

## Learning outcomes

By the end of this release you can:

- **Explain the five separations** — `priority-map.md` (WHO/WHAT), `auto-resolver.md`
  (WHAT-TO-DO), `tasks.md` (STATE), `skills/` (HOW), `IDENTITY.md`/`USER.md` (persona).
- **Give the agent an identity and a principal** by editing `IDENTITY.md` + `USER.md`.
- **Author the priority map** — your real people + programs + urgency + action mode.
- **Seed live task state** in `tasks.md` and have the agent read it back.
- **Re-theme without touching `skills/`** — proof the architecture is right.

## The four files that make it "you"

| File | Owns | In this example |
|---|---|---|
| `workspace/IDENTITY.md` | who the assistant is | **Anton** (calm, decisive on ops, deferential on strategy) |
| `workspace/USER.md` | who the principal is | **Richard Hendricks**, founder/CEO of Pied Piper |
| `clawchief/priority-map.md` | people + programs + urgency | Jared, Gilfoyle, Dinesh, Laurie, Gavin/Hooli… |
| `clawchief/tasks.md` | live task state | today's real work |

The repo already ships a worked **Pied Piper** version of all four — read them as the
reference, then make them yours.

## Lab steps

### 1. See the starting persona

```bash
$EXEC agent --agent main --message "Who are you and who do you work for?"
```

Out of the box (post-overlay) it already answers as **Anton** for **Richard** — that's
the shipped Pied Piper example. Now you'll change it to *you*.

### 2. Edit the identity + principal

Edit the two persona files. (Edit them in the repo, then re-overlay — Step 4 — or edit
the live copies under the workspace; the repo is the source of truth, so prefer editing
the repo.)

```bash
$EDITOR workspace/IDENTITY.md     # the assistant: name, creature, vibe, emoji
$EDITOR workspace/USER.md         # the principal: name, role, what they care about, who annoys them
```

Keep `IDENTITY.md` short and opinionated — vibe and operating posture matter more than
a bio. In `USER.md`, the "what annoys them / how they fail under pressure" lines are
what make the assistant genuinely useful.

### 3. Author the priority map (the 80% file)

```bash
$EDITOR clawchief/priority-map.md
$EDITOR clawchief/tasks.md
```

In `priority-map.md`, replace the Pied Piper people/programs with **your** real ones.
For each person/program set: *why they matter*, *what to watch for*, *when to escalate
to P0*, and the *default action mode* (Interrupt now / Handle & summarize / Queue /
Ignore). In `tasks.md`, seed a few real items under `## Today` split into
`### Principal` and `### Assistant`, grouped by the program names you just defined.

> Do **not** put any of this in `skills/`. Skills stay generic and shareable; your
> life lives in the data files. That separation is the entire point of v0.5.

### 4. Re-overlay the pack into the live workspace

The pack is baked at `/opt/clawchief` and overlaid into the running workspace. After
editing the repo files, push them in and restart so the agent reads the new self:

```bash
./docker/clawchief-up.sh overlay
docker compose -f docker/docker-compose.yml restart
```

### 5. Ask your chief of staff what matters today

```bash
$EXEC agent --agent main --message "Introduce yourself, then read clawchief/tasks.md and clawchief/priority-map.md and give me today's top 3 priorities, each with its owner. Be concrete."
```

It now answers **as your assistant**, for **you**, citing **your** priorities — and the
`skills/` directory never changed.

## Security checklist (Gilfoyle)

- **Nothing personal in `skills/`.** `grep -ri "your-name\|your-company" skills/` returns
  nothing — identities live in data files only.
- **Secrets still clean.** `git diff --staged | grep -iE 'sk-|tvly-|v1\.|BEGIN .*KEY'`
  is empty (you only edited prose files).
- **Role separation is real.** `IDENTITY.md` (assistant) and `USER.md` (principal) are
  distinct — the agent never conflates "who I am" with "who I serve".
- **No real PII you wouldn't want in git.** This is fictional Pied Piper here; for your
  own data, decide deliberately what belongs in a (possibly public) repo vs. a private
  overlay.
