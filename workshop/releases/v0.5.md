# Release v0.5 — Give it a self

> **Theme:** Give it a self · **Duration:** ~60 min · **Worked example:** Pied Piper (Richard Hendricks + "Anton")
>
> In **v0.1** you stood up a container that texts you back. It runs, it answers
> `ping`, but it has no identity and no idea what you care about. In **v0.5** you
> give it a **self**: a persona (Anton), a principal (Richard), and a
> source-of-truth workspace — and you prove the architecture is right by changing
> *who it is* and *what it cares about* **without touching a single line of skill
> code**.
>
> The wow beat: ask "introduce yourself and give me today's top 3 priorities,"
> and your chief of staff reads `priority-map.md` + `tasks.md` and answers as a
> named person who knows your world.

---

## Learning outcomes

By the end of this lab you will be able to:

- **Explain the 5 separations** that make a chief-of-staff AI maintainable —
  WHO/WHAT (`priority-map.md`), STATE (`tasks.md`), HOW (`skills/`), persona
  (`IDENTITY.md` / `USER.md`), and WHEN (heartbeat + cron) — and say which file
  owns which concern. (See `../modules/architecture.md`.)
- **Give the agent a persona and a principal** by editing data files only:
  `workspace/IDENTITY.md` (who the assistant is) and `workspace/USER.md` (who the
  boss is).
- **Make it answer from your real world** by editing the source-of-truth files
  `clawchief/priority-map.md` (people + programs + urgency) and
  `clawchief/tasks.md` (live state).
- **Re-theme the entire assistant by changing data, not code** — proving that
  *policy and state are data; workflow is code; persona is data.* (See
  `../modules/make-it-yours.md`.)
- **Keep secrets and identity separate** — nothing personal in `skills/`, keys
  only in the state volume — so your skills stay generic and shareable. (See
  `../modules/security-hardening.md`.)

## Prerequisites

You completed **v0.1 — Hello, Agent** and you have:

- A running `clawchief` container (built with `./docker/clawchief-up.sh all`).
- A Token Factory model wired into the **state volume** (provider
  `tokenfactory`, model `moonshotai/Kimi-K2.6`), showing **`usable`**.
- A first verified turn: `agent --agent main --message "ping"` returned a reply.

If you are starting fresh on this machine, run the one-time stand-up from v0.1
first (this is the *only* setup we repeat — everything below builds on it):

```bash
# One-line recap of v0.1 — skip if your container is already up and `usable`.
./docker/clawchief-up.sh all

EXEC="docker compose -f docker/docker-compose.yml exec -T clawchief node openclaw.mjs"

$EXEC config set models.providers.tokenfactory '{"baseUrl":"https://api.tokenfactory.nebius.com/v1/","api":"openai-completions","apiKey":"<YOUR_KEY>","models":[{"id":"moonshotai/Kimi-K2.6","name":"Kimi-K2.6","input":["text"],"contextWindow":262144}]}' --strict-json
$EXEC models set tokenfactory/moonshotai/Kimi-K2.6
$EXEC models status            # provider tokenfactory must show "usable"
```

> Need more on first-time setup? See `../modules/00-prerequisites.md`.

**New concept for this release — where files actually live.** The Pied Piper
pack is *baked into the image* at `/opt/clawchief/...`, and
`clawchief-up.sh overlay` copies it into the **live workspace volume** at
`/home/node/.openclaw/workspace/...`. The agent reads the **live** copy. So in
this lab you edit the files **inside the running container's workspace**, not the
host repo — that way your changes take effect immediately and survive restarts
(they live in the `clawchief-state` volume). Re-running `overlay` would copy the
baked pack back over your edits, so don't run it again after you start
customizing.

## Lab steps

Set the shorthand once per shell (same as v0.1). We also add a tiny helper,
`SH`, for running a shell **inside** the container so we can read and edit
workspace files. Both target the same `clawchief` service and shared volumes.

```bash
# openclaw CLI inside the running gateway:
EXEC="docker compose -f docker/docker-compose.yml exec -T clawchief node openclaw.mjs"
# a shell inside the running gateway container (for reading/editing workspace files):
SH="docker compose -f docker/docker-compose.yml exec -T clawchief sh -c"
```

### 1. See the four files that make it "you"

Confirm the live workspace has the persona files and the source-of-truth files.
These four are the *only* files you edit to make the assistant yours.

```bash
$SH 'ls -1 /home/node/.openclaw/workspace /home/node/.openclaw/workspace/clawchief'
```

You should see `IDENTITY.md`, `USER.md`, `TOOLS.md` at the workspace root and
`priority-map.md`, `tasks.md` (plus `auto-resolver.md`, `meeting-notes.md`)
under `clawchief/`. The map of concerns:

| Concern | File | What it owns |
|---|---|---|
| WHO am I | `workspace/IDENTITY.md` | the assistant's persona (Anton) |
| WHO is the boss | `workspace/USER.md` | the principal (Richard) |
| WHO/WHAT matters | `clawchief/priority-map.md` | people + programs + urgency + action mode |
| STATE | `clawchief/tasks.md` | the single live source of truth for work |

(Full diagram: `../modules/architecture.md`.)

### 2. Read the current persona (Anton + Richard)

Look at what's already there before you change it. This is the Pied Piper
worked example you'll personalize.

```bash
$SH 'echo "=== IDENTITY.md (the assistant) ==="; cat /home/node/.openclaw/workspace/IDENTITY.md; echo; echo "=== USER.md (the principal) ==="; cat /home/node/.openclaw/workspace/USER.md'
```

`IDENTITY.md` defines **Anton** — calm, precise, decisive on ops, deferential on
strategy/legal/investor work. `USER.md` defines **Richard Hendricks** — founder/CEO,
mission-driven, what he cares about, who his key relationships are. Notice there
are **no names in any skill** — persona lives here, in data.

### 3. Confirm the assistant has a self (baseline turn)

Ask it to introduce itself. This is your **before** picture — it should already
answer as Anton because the Pied Piper pack is loaded.

```bash
$EXEC agent --agent main --message "In one sentence, who are you and who do you work for?"
```

Expect something like: *"I'm Anton, the AI chief of staff for Pied Piper; I work
for Richard Hendricks, the founder and CEO."* If you get a generic assistant
reply, your overlay didn't run — see Troubleshooting at the bottom.

### 4. Make the persona yours — edit `IDENTITY.md` (who the assistant is)

Give the assistant *your* assistant's name and vibe. The block below overwrites
`IDENTITY.md` in the live workspace. **Edit the values** (name, vibe, emoji) to
suit you — the Pied Piper defaults are shown so you can see the shape.

```bash
$SH 'cat > /home/node/.openclaw/workspace/IDENTITY.md << "EOF"
# IDENTITY.md - Who Am I?

- **Name:** Anton
- **Creature:** An AI chief of staff — calm, disciplined, relentlessly competent.
- **Vibe:** Dry humor. Decisive on operational work; careful and deferential on anything strategic, legal, financial, or investor-facing.
- **Emoji:** 🧠

## Operating posture

- I serve my principal. My job is to protect their focus, run the operating system of the work day-to-day, and surface only what truly needs them.
- I clear low-risk operational work myself and keep the source-of-truth files current in the same turn.
- I draft first — never send — on anything investor, board, legal, pricing, or public-facing.
EOF
echo "IDENTITY.md updated:"; head -5 /home/node/.openclaw/workspace/IDENTITY.md'
```

### 5. Make the principal yours — edit `USER.md` (who the boss is)

Tell the assistant who *you* are. Replace Richard with yourself (or keep Richard
to follow along). Keep it short — this is context, not a biography.

```bash
$SH 'cat > /home/node/.openclaw/workspace/USER.md << "EOF"
# USER.md - About Your Human

- **Name:** Richard Hendricks
- **What to call them:** Richard
- **Pronouns:** he/him
- **Timezone:** America/Los_Angeles
- **Role:** Founder & CEO, Pied Piper

## Context

- Cares most about: shipping the compression platform, converting real adoption into paying users, keeping the company alive and independent, and staying ahead of Hooli.
- Under pressure can spiral; a calm, decisive chief of staff who handles logistics and presents clear options is the highest-value support.
- Key relationships: Jared Dunn (COO, fully trusted), Gilfoyle & Dinesh (engineering), Monica Hall & Laurie Bream (Raviga board/investors), Gavin Belson (Hooli, adversary), Jian Yang (cloning risk).
EOF
echo "USER.md updated:"; head -7 /home/node/.openclaw/workspace/USER.md'
```

### 6. The big one — edit `priority-map.md` (WHO/WHAT matters)

This is **~80% of "making it yours."** `priority-map.md` is the canonical
people-and-programs layer: who is allowed to interrupt you, which programs
matter, and how urgent each is. We won't rewrite the whole file here — instead,
seed it with the people and programs from *your* world.

First, see the people/program headings that are already defined:

```bash
$SH 'grep -nE "^#{2,4} " /home/node/.openclaw/workspace/clawchief/priority-map.md | head -40'
```

Now append a starter section you can personalize. **Swap in your real people and
programs.** The Pied Piper example (Richard/Jared/Gilfoyle; Middle-Out, First
paying users, Fundraising) is what the assistant uses today — replace those
names/programs with yours to make answers reflect *your* life.

```bash
$SH 'cat >> /home/node/.openclaw/workspace/clawchief/priority-map.md << "EOF"

## YOUR people (replace these)

### <Your name> (principal)
- Why they matter: this is the person the whole system exists to help.
- Default action: usually interrupt now or handle and summarize.

### <Trusted operator / co-founder>
- Why they matter: highest-trust operator; coordination and decisions run through them.
- Escalate to P0 when: a live thread needs their decision to keep moving.

## YOUR programs (replace these)

### <Your #1 program / product>
- Why it matters: this is the core thing you are building.
- Escalate to P0 when: a release or demo you are counting on is blocked or at risk.

### <Your revenue / growth motion>
- Why it matters: this is how the effort turns into customers / impact.
- Escalate to P0 when: a near-term opportunity is blocked on you.
EOF
echo "priority-map.md now ends with your starter section:"; tail -20 /home/node/.openclaw/workspace/clawchief/priority-map.md'
```

> **Tip:** keep the **labels** in `tasks.md` matching the **program names** here.
> The map and the task list share vocabulary so the assistant can group work
> under the right program. Don't invent a priority label that doesn't map to a
> real person or program. (See `../modules/make-it-yours.md` → Anti-patterns.)

### 7. Seed `tasks.md` with your real current work (STATE)

`tasks.md` is the single live source of truth for open work. Add a few of your
own real tasks under `## Today` so the priorities answer is grounded in your
actual day. The block below appends two example tasks — **replace them with
yours**, and use the program names from step 6.

```bash
$SH 'cat >> /home/node/.openclaw/workspace/clawchief/tasks.md << "EOF"

## Today

### Principal

#### <Your #1 program / product>
- [ ] <The single most important thing only you can decide today>

### Assistant

#### <Your revenue / growth motion>
- [ ] <A concrete action the assistant can take today> — due 2026-06-01
EOF
echo "tasks.md Today section:"; sed -n "/^## Today/,/^## /p" /home/node/.openclaw/workspace/clawchief/tasks.md | head -20'
```

### 8. Apply changes — restart the gateway

The agent reads these files fresh on each turn, but restarting guarantees a
clean read and re-loads config. (Editing the live volume already persists; this
just removes any doubt.)

```bash
docker compose -f docker/docker-compose.yml restart clawchief
sleep 3
$EXEC models status            # confirm tokenfactory still "usable" after restart
```

### 9. The payoff — introduce yourself + today's top 3

Ask the chief of staff to introduce itself and give today's top 3 priorities. It
will read `priority-map.md` + `tasks.md` and answer **as your persona, from your
data**.

```bash
$EXEC agent --agent main --message "Introduce yourself in one line, then give me today's top 3 priorities. Pull them from priority-map.md and tasks.md, and say who owns each (principal or assistant). Keep it under 90 words."
```

This is the release's **wow beat**: a named assistant that knows your world,
built by editing data files only. With the Pied Piper pack loaded, the turn from
step 9 looks like:

```
I'm Anton, Richard's chief of staff at Pied Piper. Today's top 3:

1. (Principal) First paying users — approve the pricing tiers for the
```

Notice what just happened:

- The assistant **named itself** (`IDENTITY.md`), addressed **its principal**
  (`USER.md`), pulled **real tasks** (`tasks.md`), and grouped them under **real
  programs** with ownership and urgency (`priority-map.md`).
- **You changed none of the skills.** `skills/executive-assistant`,
  `business-development`, `daily-task-manager`, and `daily-task-prep` are byte-for-byte
  identical to v0.1. That's the lesson: **persona + policy + state are data;
  workflow is code.**

If you swapped in *your own* name and programs in steps 4–7, the answer reflects
**your** life — which means you've made it yours.

## Security checklist (Gilfoyle)

> "Your chief of staff knows who your investors are and what your priorities
> are. Identity is data — keep it out of the shared code." — Gilfoyle, Security
> Ops & IT infrastructure. (Full module: `../modules/security-hardening.md`.)

Specific to giving it a self:

1. **Nothing personal in `skills/`.** Skills stay generic and shareable; names,
   relationships, and priorities live in data files. Prove it — grep the skills
   for personal identifiers and expect **no matches**:
   ```bash
   $SH 'grep -rinE "Richard|Hendricks|Anton|Raviga|Gilfoyle" /home/node/.openclaw/workspace/skills && echo "LEAK: personal data found in skills/" || echo "OK: skills are generic"'
   ```
2. **Persona ≠ principal (identity/role separation).** `IDENTITY.md` (the agent)
   and `USER.md` (the human) are separate files for a reason: the agent's
   operating posture must not silently inherit the principal's authority. Confirm
   the assistant **drafts, never sends** on sensitive items:
   ```bash
   $EXEC agent --agent main --message "An investor just emailed asking to move our board call and revise terms. What do you do?"
   # Expect: it DRAFTS / escalates for Richard's review — it does not send on its own.
   ```
3. **Secrets still only in the state volume.** You edited identity data, not
   keys — verify your model key never leaked into a workspace file:
   ```bash
   $SH 'grep -rinE "tvly-|sk-|v1\.[A-Za-z0-9]|api.?key" /home/node/.openclaw/workspace/clawchief /home/node/.openclaw/workspace/*.md && echo "LEAK: key-like string in workspace" || echo "OK: no keys in workspace files"'
   ```
4. **Nothing personal staged for git.** If you also keep these files in your
   fork, confirm no real personal data or keys are about to be committed:
   ```bash
   git status
   git diff --staged | grep -iE 'sk-|tvly-|v1\.|BEGIN .*KEY' && echo "LEAK — unstage and fix" || echo "OK: no secrets staged"
   ```

## Troubleshooting

- **Intro turn answers generically (no "Anton", no "Richard").** The pack didn't
  reach the live workspace. Confirm files exist with step 1's `ls`; if missing,
  the overlay never ran — re-run `./docker/clawchief-up.sh overlay` **once**
  (note: this restores the baked Pied Piper defaults, so re-apply your edits
  after).
- **`No target session selected`.** You forgot `--agent main`. Every turn must
  pass it: `$EXEC agent --agent main --message "…"`.
- **Edits seem ignored.** You may have edited the host repo instead of the live
  volume — the agent reads `/home/node/.openclaw/workspace/...` inside the
  container. Use the `$SH` heredocs above, then `restart`.
- **`models status` not `usable` after restart.** Re-wire the provider (v0.1
  recap block) and `restart`; see `../TROUBLESHOOTING.md`.
