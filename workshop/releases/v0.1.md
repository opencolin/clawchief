# Release v0.1 — Hello, Agent

> **The one-line promise:** a container that texts you back.
>
> By the end of this release you have OpenClaw running in Docker, wired to your
> own Nebius Token Factory key, answering a real model turn — and the key lives
> only inside the container's state volume, never in your repo.

This is the **first** release of the workshop *Build Your Own Chief-of-Staff AI*.
The worked example is **Pied Piper**: principal **Richard Hendricks** (CEO), an AI
chief of staff named **Anton**, with **Bertram Gilfoyle** owning Security Ops & IT.
In v0.1 you stand up the bare runtime; Anton gets his persona, data, and skills in
later releases. Today the win is simpler and load-bearing: *the box is alive, it
thinks on your key, and it leaks nothing.*

Companion reading: `../modules/00-prerequisites.md` and `../modules/architecture.md`
(intro). When something breaks, `../TROUBLESHOOTING.md` has the eight issues this
room actually hits.

## Learning outcomes

By the end of this release you can:

- **Stand up OpenClaw in Docker** with one script (`./docker/clawchief-up.sh all`) —
  build → onboard → overlay → start — and explain what each phase does.
- **Wire a Token Factory model** (OpenAI-compatible) via the OpenClaw config CLI and
  confirm the provider reports `usable` with `models status`.
- **Run a real agent turn** (`agent --agent main --message "ping"`) and read the reply.
- **Keep the model key out of the repo** — injected into the container *state volume*,
  with `.gitignore` and a secret-scan proving zero secrets are tracked.
- **Reason about the security posture**: loopback gateway bind, no published host ports,
  non-root `node` user — and *why* each matters for an agent that can spend your money.

## Prerequisites

v0.1 is the first release, so the only assumptions are:

- **Docker is installed and running** (Docker Desktop / Colima / OrbStack). Confirm
  `docker compose version` prints a version. If `docker compose` is missing, see the
  `docker: unknown command: docker compose` fix in `../TROUBLESHOOTING.md`.
- **A Nebius Token Factory API key** (OpenAI-compatible; looks like `v1.…`). Get it from
  the Token Factory console → API keys. No model runs on your laptop — that is the whole
  point: a strong agent brain with **zero local GPU**.
- **Git** (preinstalled on macOS/Linux) to fork and clone.

You do **not** need a Tavily key, a Google OAuth client, or any persona/workspace
customization yet — those arrive in v1.0 and v0.5 respectively. Full prerequisite
table: `../modules/00-prerequisites.md`.

## One-time recap (the only setup before the lab)

Fork, clone, and create your env file. This is the entire "before we start" step:

```bash
# Fork + clone your own copy
gh repo fork snarktank/clawchief --clone        # → your-name/clawchief
cd clawchief

# Create your env file (sets the gog keyring passphrase; the MODEL key does NOT go here)
cp docker/.env.example docker/.env              # edit GOG_KEYRING_PASSWORD to a long random string
```

> Your **model key is injected into the state volume in Step 3**, not into
> `docker/.env`. The `.env` file only holds the `gog` keyring passphrase for a later
> release. Keep it that way — `docker/.env` is gitignored precisely so a key that
> *did* land there could never be committed.

## Lab steps

Set the shorthand once per shell. Every command below uses it.

```bash
EXEC="docker compose -f docker/docker-compose.yml exec -T clawchief node openclaw.mjs"
```

### 1. Build the image and stand up the gateway

One script runs all four phases: **build** the image → **onboard** the gateway with
auth skipped (so it stands up without a model) → **overlay** the Pied Piper pack into
the live workspace → **up** (start the gateway, loopback-bound, no ports published).

```bash
./docker/clawchief-up.sh all
```

Expected tail: the overlay lists the workspace contents and `status` prints the
gateway state plus the skills list. (The "Gateway did not become reachable …
ECONNREFUSED 18789" line *during onboarding* is expected — onboarding runs in a
one-off container and `--skip-health` is set; the gateway starts in the `up` phase.
See `../TROUBLESHOOTING.md`.)

### 2. Wire your Token Factory model (key goes into the state volume)

Register the Token Factory provider (OpenAI-compatible, baseUrl
`https://api.tokenfactory.nebius.com/v1/`) with **your** key, then select the model.
The `config set … <KEY>` writes into the container's **state volume**, never a tracked
file.

```bash
$EXEC config set models.providers.tokenfactory '{"baseUrl":"https://api.tokenfactory.nebius.com/v1/","api":"openai-completions","apiKey":"<YOUR_TOKEN_FACTORY_KEY>","models":[{"id":"moonshotai/Kimi-K2.6","name":"Kimi-K2.6","input":["text"],"contextWindow":262144}]}' --strict-json

$EXEC models set tokenfactory/moonshotai/Kimi-K2.6
```

> Replace `<YOUR_TOKEN_FACTORY_KEY>` with your real key. Paste it **only** into this
> command — do not put it in any file. (Production: use a SecretRef / file batch
> instead of a literal on the command line, and delete the batch file afterward — see
> `../modules/security-hardening.md`.)

### 3. Confirm the provider is `usable`

```bash
$EXEC models status
```

You're looking for the **tokenfactory** provider line to read **`usable`** with
`moonshotai/Kimi-K2.6` selected. If it doesn't, the key didn't resolve — re-run Step 2
and re-check (see "`models status` shows the model but turns fail" in
`../TROUBLESHOOTING.md`).

### 4. Get your first reply — the agent turn

The chat turn **must** pass `--agent main` (without it you get
"No target session selected").

```bash
$EXEC agent --agent main --message "ping"
```

A reply comes back from the model. That's the whole game for v0.1: the container
just thought on your key and answered.

### 5. Prove the key never touched the repo (Gilfoyle's gate)

Confirm `.gitignore` is in place and scan the working tree + any staged diff for
secret-shaped strings. This must come back **empty**.

```bash
git status
git diff --staged | grep -iE 'sk-|tvly-|v1\.|BEGIN .*KEY' || echo "CLEAN: no secrets staged"
```

`CLEAN: no secrets staged` (and nothing secret in `git status`) means the key lives
only in the `clawchief-state` volume, exactly as it should.

### 6. (Optional) Confirm no host ports are published

The gateway binds loopback *inside* the container and publishes nothing to the host by
default — you drive it via `docker compose exec`, not a browser. Verify there's no
mapped port:

```bash
docker compose -f docker/docker-compose.yml ps
```

The `clawchief` service should show **no** `0.0.0.0:`/`127.0.0.1:…->…` port mapping.
(The Control UI port is commented out in `docker/docker-compose.yml` — leave it that
way unless you have a reason, and even then bind it to `127.0.0.1` only.)

```text

$ $EXEC models status
```

Exact wording of the reply will vary (it's a live model). What matters: a reply
returns, `models status` says `usable`, and the secret scan is clean. Tease the

Pied Piper's chief of staff, reading Richard's priorities."*

## Security checklist (Gilfoyle)

> "Your chief of staff will read your email and spend your money. We start treating
> its credentials seriously on day one." — Gilfoyle, Security Ops & IT

Concrete checks for **this** release:

- [ ] **Key is in the state volume, not the repo.** Step 5's secret scan returns
      `CLEAN`, and `git status` shows no key-bearing file. The Token Factory key was
      passed only via `config set` (Step 2), landing in `clawchief-state`.
- [ ] **`.gitignore` blocks the obvious leaks.** It ignores `docker/.env`,
      `**/client_secret*.json`, `**/*credentials*.json`, and `.gog/`. Confirm with
      `git check-ignore docker/.env` (it should echo the path).
- [ ] **No published host ports.** `docker compose ps` (Step 6) shows no port mapping;
      the gateway is loopback-only and driven via `docker exec`.
- [ ] **Runs as non-root.** The container runs as the `node` user (uid 1000), not root.
      Spot-check: `docker compose -f docker/docker-compose.yml exec -T clawchief whoami`
      → `node`.

If a real key ever appears in a terminal, chat, or ticket, treat it as compromised and
rotate it (Token Factory console → re-inject via `config set`). Full policy:
`../modules/security-hardening.md`.

## Definition of done

Pass/fail — all five must be true:

- [ ] `./docker/clawchief-up.sh all` completed; `docker compose ps` shows `clawchief`
      **Up**.
- [ ] `$EXEC models status` shows the **tokenfactory** provider as **`usable`** with
      `moonshotai/Kimi-K2.6` selected.
- [ ] `$EXEC agent --agent main --message "ping"` returns a model reply.
- [ ] Secret scan is **clean**: `git diff --staged | grep -iE 'sk-|tvly-|v1\.|BEGIN .*KEY'`
      prints nothing, and no key-bearing file appears in `git status`.
- [ ] No host ports are published (`docker compose ps` shows no port mapping) and
      `whoami` in the container is `node`.

If any line fails, jump to `../TROUBLESHOOTING.md` before moving on — v0.5 builds
directly on a healthy, non-leaking container.

**Facilitation notes**

- Front-load the destination before the mechanics; attendees build faster once they've
  seen where it's going (`../INSTRUCTOR.md`).
- Pair attendees: one drives Docker, one watches output and runs the secret scan.
- The single most common stall is Step 2/3 (provider not `usable` because the key
  didn't resolve). Keep `../TROUBLESHOOTING.md` open on the projector.
- Protect the security beat (Steps 5–6) — it's short, and it's the habit the whole
  workshop reinforces every release.
