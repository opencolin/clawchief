# Release v1.5 — It acts on its own

> A reactive bot waits to be asked. A **chief of staff** wakes itself up.
>
> In v1.0 Anton gained hands and senses (skills + Tavily + Google). In v1.5 he
> gains a **clock**: a 30-second heartbeat that quietly checks "anything need
> me?" on a cheap brain, plus scheduled **cron sweeps** that run the
> executive-assistant workflow on a timer. The wow beat: `system heartbeat last`
> ticking on Nemotron, silently, every 30 seconds — and a cron-registered EA
> sweep that will fire on its own during the work day.
>
> Modules behind this release: `../modules/crons-and-heartbeat.md` (the "WHEN"
> layer) and `../modules/security-hardening.md` (cost-as-ops-risk, the kill switch).

---

## Learning outcomes

By the end of this lab you will be able to:

- Explain the **two clocks** — the interval **heartbeat** (sub-minute, lightweight) vs. minute-granularity **cron** (heavier scheduled jobs) — and pick the right one for a job.
- Enable a **30s heartbeat** that runs on a cheap model (Nemotron) and stays **silent by default**, driven by `HEARTBEAT.md` → `auto-resolver.md`.
- Register a **cron EA sweep** whose prompt is one line, letting the `executive-assistant` skill carry the workflow.
- Locate the **WHEN** layer inside the 5-separations architecture (heartbeat + cron = *when the agent acts*; the skill = *how*; the auto-resolver = *what to do*).
- Operate the heartbeat as a **billing/availability risk**: prove silence, and use `system heartbeat disable` as the kill switch.

## The mental model (60-second read before you type)

This release adds the **WHEN** layer to the architecture you met in `../modules/architecture.md`:

| Layer | File / mechanism | Owns |
|---|---|---|
| WHO / WHAT matters | `clawchief/priority-map.md` | people & program priority, urgency |
| WHAT to do next | `clawchief/auto-resolver.md` | act vs. draft vs. escalate vs. ignore |
| STATE | `clawchief/tasks.md` | live task state |
| HOW | `skills/` | the detailed workflows |
| persona | `workspace/IDENTITY.md`, `workspace/USER.md` | who the agent is, who you are |
| **WHEN** | **heartbeat + cron** | **when the agent acts on its own** |

Two clocks do the "when":

| Mechanism | Cadence | Use |
|---|---|---|
| **Heartbeat** | interval (`30s` … `30m`) | frequent, lightweight "anything need me?" checks; runs `HEARTBEAT.md`, which delegates to the auto-resolver |
| **Cron** | schedule (`*/15 8-21 * * *`) | heavier scheduled jobs: inbox sweep, daily task-prep |

The heartbeat reads `workspace/HEARTBEAT.md`, which is an **orchestrator, not a workflow**: it points at the priority map, the auto-resolver, the meeting-notes policy, and the live tasks, then replies **`HEARTBEAT_OK`** when there is nothing worth saying. That single design choice — cheap model + silence-by-default — is what lets you tick every 30 seconds without going broke.

## Lab steps

### 1. Point the heartbeat at a cheap brain

The default model (Kimi-K2.6) is your "thinking" brain — too expensive to fire every 30 seconds. Point the heartbeat at **Nemotron** instead. (This is the same Nemotron you'll fully adopt as the brain-swap reveal in v2.0; here it is just the cheap tick engine.)

```bash
$EXEC config set agents.defaults.heartbeat.model '"tokenfactory/nvidia/Nemotron-3-Nano-Omni"'
```

### 2. Set the heartbeat interval to 30 seconds

```bash
$EXEC config set agents.defaults.heartbeat.every '"30s"'
```

> The value is a quoted duration string (`"30s"`, `"5m"`, `"30m"`). The outer
> single quotes keep your shell from eating the inner double quotes — `--strict-json`
> is not needed for a bare scalar, but the quoting is.

### 3. Enable the heartbeat

```bash
$EXEC system heartbeat enable
```

The scheduler now wakes the agent every 30 seconds. Each tick: read the priority map → read the auto-resolver → read meeting-notes + tasks → run the EA workflow for triage → auto-resolve the obvious, low-risk items → say something only if Richard truly needs to know. Otherwise: `HEARTBEAT_OK`.

### 4. Watch it tick — silently — on Nemotron

Inspect the most recent tick. The interesting fields are `reason` (why it woke), `silent` (did it stay quiet), and `status`.

```bash
$EXEC system heartbeat last
```

Run it two or three times over ~90 seconds. You want to see `reason:"interval"` and `silent:true` — proof the agent is alive, thinking on the cheap brain, and **choosing not to interrupt** because nothing is actionable.

### 5. Register the cron EA sweep

Now add a **scheduled** job. The EA sweep runs the executive-assistant skill every 15 minutes during the work day (08:00–21:00 Pacific). Note the prompt is deliberately **one line** — the skill carries the workflow, so this same cron survives skill upgrades.

```bash
$EXEC cron add --name "EA sweep" --schedule "*/15 8-21 * * *" --tz America/Los_Angeles \
  --session-target main \
  --text "Executive assistant sweep. Use the executive-assistant skill. Handle this internally and only message Richard if there is new actionable information."
```

### 6. Confirm the job is registered

```bash
$EXEC cron list
```

You should see **EA sweep** listed with its `*/15 8-21 * * *` schedule, `America/Los_Angeles` timezone, and session target `main`.

> **Gotcha worth knowing:** the gateway's scheduler reads its jobs at startup. If
> cron is disabled at the gateway level, jobs are accepted but **never fire — and
> nothing errors**. `cron list` showing your job is your proof it registered;
> seeing the next run land during the 08:00–21:00 window is your proof the
> scheduler is actually running. (Full cron-enablement lifecycle lives in
> `../modules/crons-and-heartbeat.md`.)

### 7. (Optional) Add a silent daily task-prep cron

A second, heavier job — runs once at 02:00 in an **isolated** session (fresh context) and delivers nothing to Richard; it just refreshes `clawchief/tasks.md` before the day starts so the first morning heartbeat has clean state to read.

```bash
$EXEC cron add --name "Daily task prep" --schedule "0 2 * * *" --tz America/Los_Angeles \
  --session-target isolated --message "Use the daily-task-prep skill." --delivery none
```

### 8. Force a visible heartbeat (the "it surfaced a task on its own" beat)

Silence is correct, but you want to *see* the agent act. Give it a reason: add a task with a near-now due time, then let the next heartbeat find it. Edit `clawchief/tasks.md` (host-side, in your repo) and drop a line under **## Today → ### Principal**, for example:

```markdown
#### First paying users / customers
- [ ] Sign off on the launch pricing page — due 2026-05-31 17:00 America/Los_Angeles
```

Wait for the next 30s tick, then re-inspect:

```bash
$EXEC system heartbeat last
```

This time the heartbeat has a genuine, time-pressing item grounded in the live task file — exactly the auto-resolver's "surface it to the principal" path. (If it instead resolves it quietly, that is also correct behavior — read the `auto-resolver.md` lanes to see why.)

### 9. Prove the kill switch

Cost is a security concern (see the Gilfoyle checklist below). Stop the ticks on demand:

```bash
$EXEC system heartbeat disable
```

Re-enable when you want it back on with `$EXEC system heartbeat enable`. **Leave the heartbeat enabled** at the end of the lab so the room can keep watching it tick.

## Demo / what you'll see

**The beat:** "He wakes himself up." After steps 1–4, run the inspector a couple of times across ~90 seconds:

```bash
$EXEC system heartbeat last
```

Expected (shape; exact fields vary by build):

```json
{ "reason": "interval", "status": "ok-token", "silent": true }
```

That is the whole story in one line: `reason:"interval"` = it woke itself, not you; `silent:true` = it read the priority map, auto-resolver, and tasks, found nothing worth your attention, and **stayed quiet**; and it did all of that on **Nemotron**, the cheap brain — not your expensive Kimi-K2.6.

Then `cron list` shows **EA sweep** armed on `*/15 8-21 * * *`. During the work-day window it will run the executive-assistant skill on its own — meeting-notes ingestion, inbox/calendar triage, low-risk auto-resolution — and message Richard **only** if there is new actionable information. After step 8, a heartbeat surfaces your freshly-added, time-pressing task, e.g.:

```
Heads up: launch pricing-page sign-off is due at 5pm today and still open.
Want me to block 30 min on your calendar before then?
```

The room's reaction: it stopped being a chatbot. It is now an operator with a clock.

## Security checklist (Gilfoyle)

> "Your chief of staff can read your email and spend your money. An agent that
> wakes itself up every 30 seconds can do both **on a loop**. Treat its cadence
> like a budget line." — see `../modules/security-hardening.md`, §6.

- [ ] **Cheap brain on the tick.** Confirm `agents.defaults.heartbeat.model` is `tokenfactory/nvidia/Nemotron-3-Nano-Omni`, **not** the primary Kimi-K2.6. A 30s heartbeat on the expensive model is a runaway billing risk.
  ```bash
  $EXEC config get agents.defaults.heartbeat.model
  ```
- [ ] **Silent by default.** `system heartbeat last` shows `silent:true` on idle ticks. If every tick is chatty, the agent is generating noise (and cost) — re-read `HEARTBEAT.md`; it must end with `HEARTBEAT_OK` when there is nothing to do.
- [ ] **Kill switch rehearsed.** You have run `$EXEC system heartbeat disable` at least once and know it halts ticks immediately. This is your circuit-breaker for a stuck loop or a billing spike.
- [ ] **No secrets leaked by the new config.** Nothing in this release writes to the repo — heartbeat/cron config lives in the container state volume. Confirm before any commit:
  ```bash
  git status && git diff --staged | grep -iE 'sk-|tvly-|v1\.|BEGIN .*KEY'   # expect: no matches
  ```

## Definition of done

Pass requires **all** of the following:

- [ ] `system heartbeat last` returns `reason:"interval"` and `silent:true` on idle ticks.
- [ ] The heartbeat model is **Nemotron** (`config get agents.defaults.heartbeat.model` confirms it), not Kimi-K2.6.
- [ ] The interval is **30s** (`config get agents.defaults.heartbeat.every` → `"30s"`).
- [ ] `cron list` shows **EA sweep** on `*/15 8-21 * * *`, tz `America/Los_Angeles`, target `main`.
- [ ] You demonstrated the kill switch: `system heartbeat disable` stops ticks, `enable` resumes them.
- [ ] `git status` is clean of any new tracked secret or config file (the WHEN layer lives in the state volume).
- [ ] *(Optional)* the `Daily task prep` cron is listed, isolated session, `--delivery none`.

If any box is unchecked, see `../TROUBLESHOOTING.md` (the heartbeat/cost note) before moving to v2.0.
