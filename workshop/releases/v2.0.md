# Release v2.0 — The Chief of Staff, shipped

> **The capstone.** Anton already has a self, hands, senses, and a clock. This
> release makes him **portable, hardened, and demo-ready**: swap his brain to
> NVIDIA Nemotron without changing a line of the workspace, prove the box is
> locked down, run a key-rotation drill, and ship the whole thing so a colleague
> can rebuild it from a pinned, checksummed image.
>
> Owner persona for the security beats: **Bertram Gilfoyle — Security Ops & IT
> infrastructure.** "Your chief of staff can read your email and spend your
> money. Treat its credentials accordingly."
>
> **Duration:** ~80 minutes. Builds directly on **v1.5**.

---

## Learning outcomes

By the end of this release you will be able to:

- **Swap the model under a running agent** (the "nemoclaw" move) — prove the
  chief of staff is the *workspace + skills + policies*, not the model — and pin
  it as a named alias so any teammate gets the same brain.
- **Run the secrets audit** Gilfoyle requires before every commit, and show your
  fork tracks **zero** plaintext keys.
- **Execute a key-rotation drill end to end** — rotate a Token Factory key into
  the state volume, confirm the provider is still `usable`, and revoke the old key.
- **Read the supply-chain posture** of the build: a pinned base image and a
  version-pinned, checksum-verifiable `gog` binary instead of curl-pipe-to-shell.
- **Ship it**: hand someone a repo + a key and have them reproduce your hardened
  chief of staff with `./docker/clawchief-up.sh all`.

## Lab steps

### Part A — Swap the brain (nemoclaw)

#### 1. Prove the swap works per-run with `--model`

The chief of staff is model-agnostic: the same workspace that drives Kimi-K2.6
drives Nemotron. Ask Anton for a real standup, but route this one turn through
`tokenfactory/nvidia/Nemotron-3-Nano-Omni`. Nothing in the workspace changes.

```bash
$EXEC agent --agent main \
  --model tokenfactory/nvidia/Nemotron-3-Nano-Omni \
  --message "As Anton (Richard's chief of staff at Pied Piper), give Richard a crisp 3-line standup for today: the single top priority, one risk to watch (Hooli or Jian Yang), and what you'll handle yourself. Under 60 words."
```

Cross-reference: [`../demos/nemoclaw.md`](../demos/nemoclaw.md).

#### 2. Pin the brain as a named alias

A per-run `--model` flag is great for demos; a named alias is what you **ship** so
every teammate and every cron can say `nemoclaw` and get the same model.

```bash
$EXEC models aliases add nemoclaw tokenfactory/nvidia/Nemotron-3-Nano-Omni
$EXEC models aliases list            # nemoclaw → tokenfactory/nvidia/Nemotron-3-Nano-Omni
```

#### 3. Run the same prompt through the alias

Confirm the alias resolves to the same brain — identical workspace, identical
persona, different model selected by name.

```bash
$EXEC agent --agent main --model nemoclaw \
  --message "Same as before, Anton: today's top priority, one risk, what you'll handle. Under 60 words."
```

> **Teaching point.** Steps 1–3 are the whole v2.0 thesis: the "chief of staff" is
> the workspace + skills + policies (the
> [five separations](../modules/architecture.md)); the model is a swappable
> component you select per-run with `--model` or pin by name with an alias. You
> just proved portability without touching a single `clawchief/` or `workspace/`
> file.

### Part B — Harden the box (Gilfoyle)

#### 4. Audit that secrets never live in the repo

Before anything ships, prove your fork tracks **zero** plaintext keys. `.gitignore`
already blocks the obvious leaks (`docker/.env`, `*client_secret*.json`,
`*credentials*.json`, `gog-home/`, `.gog/`) — this step proves nothing slipped
past it. Model and Tavily keys live in the **`clawchief-state` volume**, never in
git.

```bash
# 1. Nothing sensitive is staged or tracked:
git status
git diff --staged | grep -iE 'sk-|tvly-|v1\.|BEGIN .*KEY' && echo "LEAK ✋" || echo "clean ✓"

# 2. Belt-and-suspenders: scan the whole tracked tree, not just the diff:
git grep -nIE 'sk-[A-Za-z0-9]|tvly-[A-Za-z0-9]|BEGIN (RSA|OPENSSH|PRIVATE) KEY' \
  -- . ':(exclude)*.example' && echo "LEAK ✋" || echo "clean ✓"

# 3. Confirm .env is ignored, not tracked:
git check-ignore docker/.env        # prints the path = it IS ignored ✓
```

A clean tree prints `clean ✓` twice and echoes `docker/.env`. Cross-reference:
[`../modules/security-hardening.md`](../modules/security-hardening.md) §1.

#### 5. Verify container hardening (non-root, loopback, isolated state)

Confirm the runtime posture the image and compose file bake in: the agent runs as
the unprivileged **`node`** user (uid 1000), the gateway binds **loopback** with
**no host ports published**, and secrets live in **named volumes**, not
bind-mounted host paths.

```bash
# Non-root: the agent process runs as uid 1000 (node), never root.
$EXEC id                                   # → uid=1000(node) gid=1000(node)

# No published ports: the host exposes nothing for clawchief.
docker compose -f docker/docker-compose.yml ps   # PORTS column is empty

# State + secrets are isolated in named volumes (not on a sensitive host path).
docker volume ls | grep clawchief          # clawchief-state, clawchief-gog
```

You drive the gateway with `docker exec`, not an exposed dashboard — that's why
the `ports:` mapping in `docker/docker-compose.yml` stays commented out.
Cross-reference: [`../modules/security-hardening.md`](../modules/security-hardening.md) §4.

#### 6. Read the supply-chain posture (pinned image + checksummable gog)

The build is reproducible and tamper-evident: the base image is pinned and `gog`
is baked from the **official GitHub release**, architecture-matched and
version-pinned (`GOGCLI_VERSION`), **not** curl-pipe-to-shell into your shell.

```bash
# Base image is pinned in the Dockerfile (pin to a digest for production):
grep -n '^FROM ' docker/Dockerfile        # FROM ghcr.io/openclaw/openclaw:latest

# gog is a versioned release artifact, arch-matched at build time:
grep -nE 'GOGCLI_VERSION|releases/download|TARGETARCH' docker/Dockerfile

# Prove the baked binary matches the build arch (b7 = aarch64, 3e = x86-64):
docker run --rm --entrypoint sh clawchief:local -c \
  'head -c19 /usr/local/bin/gog | od -An -tx1 | tr -d " \n" | tail -c2'
```

> **Production hardening (note it, don't block on it):** pin `FROM` to a
> `@sha256:` digest and add `checksums.txt` verification for the `gog` download
> in the `RUN` step so a poisoned release can't slip in.
> Cross-reference: [`../modules/security-hardening.md`](../modules/security-hardening.md) §5.

#### 7. Confirm the cost/availability guard is still in place

A runaway 30s loop on a pricey model is both a billing risk and an availability
risk. Confirm the heartbeat is on the **cheap Nemotron** brain and **silent by
default**, and remember the kill switch.

```bash
$EXEC config get agents.defaults.heartbeat.model   # → "tokenfactory/nvidia/Nemotron-3-Nano-Omni"
$EXEC system heartbeat last                         # → reason:interval, silent:true
# Kill switch (cost control): $EXEC system heartbeat disable
```

Cross-reference: [`../modules/security-hardening.md`](../modules/security-hardening.md) §6.

### Part C — Key-rotation drill

#### 8. Treat any seen key as compromised, and rotate it

This is the drill Gilfoyle makes everyone run once. **Any** key that has touched a
chat, terminal, or ticket is compromised — rotate it. (In the build session a
Token Factory key was pasted in plaintext; this is the runbook.) Mint a **new**
key in the Token Factory console first, then inject it into the state volume —
**only** the `apiKey` field changes; the rest of the provider block (baseUrl, api,
models) stays exactly as you set it in v0.1.

```bash
# 1. Inject the NEW key into the state volume (replace <NEW_KEY>; quote it):
$EXEC config set models.providers.tokenfactory.apiKey '<NEW_KEY>'

# 2. Re-apply / restart so the gateway reloads the provider:
docker compose -f docker/docker-compose.yml restart clawchief

# 3. Confirm the provider is STILL usable on the new key:
$EXEC models status            # tokenfactory → usable

# 4. Smoke-test a real turn on the rotated key:
$EXEC agent --agent main --message "ping"

# 5. Now revoke the OLD key in the Token Factory console. Rotation done.
```

> The new key never lands in the repo — `config set` writes it into
> `clawchief-state`, which is gitignored territory by construction. Re-run the
> Step 4 secrets scan if you want to prove the rotation left no trace.
> Cross-reference: [`../modules/security-hardening.md`](../modules/security-hardening.md) §2.

### Part D — Ship it

#### 9. Make `nemoclaw` real for the next person (reproducibility check)

The deliverable of this workshop is that a colleague can rebuild your hardened
chief of staff from the repo + a key. Prove the one-command path still works and
that your alias is part of what ships.

```bash
# The full build → onboard → overlay → up path a fresh clone would run:
#   ./docker/clawchief-up.sh all
# You already have a running box, so just confirm the shipped surface:
$EXEC status                         # gateway up
$EXEC skills list                    # the four skills present
$EXEC models aliases list            # nemoclaw is pinned ✓
$EXEC cron list                      # the EA sweep (and any others) survive
```

#### 10. Final pre-ship secrets gate

The last thing before you push. One clean scan, one clean `git status`, and you're
done.

```bash
git status
git diff | grep -iE 'sk-|tvly-|v1\.|BEGIN .*KEY' && echo "DO NOT PUSH ✋" || echo "safe to ship ✓"
```

## Security checklist (Gilfoyle)

Specific to v2.0 — run all four:

- [ ] **Secrets-scan clean.** `git diff --staged | grep -iE 'sk-|tvly-|v1\.|BEGIN .*KEY'`
      and `git grep` over the tracked tree both come back empty; `git check-ignore
      docker/.env` confirms `.env` is ignored. (Step 4 / Step 10.)
- [ ] **Key rotation completed end to end.** New Token Factory key injected into
      the **state volume** (never the repo), provider still `usable`, old key
      **revoked** in the console. (Step 8.)
- [ ] **Hardened runtime confirmed.** `id` → `uid=1000(node)` (non-root); `compose
      ps` shows **no published ports** (loopback-only gateway); state + secrets in
      **named volumes**. (Step 5.)
- [ ] **Supply chain accounted for.** Base image pinned in the `Dockerfile`; `gog`
      is a **version-pinned, arch-matched release artifact** (the arch byte check
      passes), not curl-pipe-to-shell — with the production to-do noted (digest pin
      + `checksums.txt`). (Step 6.)

## Definition of done

Pass/fail — every box must be checked:

- [ ] `models aliases list` shows **`nemoclaw → tokenfactory/nvidia/Nemotron-3-Nano-Omni`**.
- [ ] `$EXEC agent --agent main --model nemoclaw --message "..."` returns an
      **in-character Anton** answer sourced from the Pied Piper workspace.
- [ ] **Secrets scan is clean** on the full tracked tree (`clean ✓`), and
      `git check-ignore docker/.env` confirms `.env` is ignored.
- [ ] **Key-rotation drill complete:** new key in the state volume, `models status`
      → `usable`, a `ping` turn succeeds on the new key, old key revoked.
- [ ] `id` → **uid 1000 (node)**, and `compose ps` shows **no published host ports**.
- [ ] Base image **pinned** and `gog` is a **versioned release** (arch byte check
      returns `b7` or `3e`).
- [ ] Heartbeat model is **Nemotron** and `system heartbeat last` is **silent**;
      you know `system heartbeat disable` is the kill switch.
- [ ] `status`, `skills list`, `models aliases list`, and `cron list` all confirm
      the shipped surface — a fresh clone + key would reproduce it with
      `./docker/clawchief-up.sh all`.
